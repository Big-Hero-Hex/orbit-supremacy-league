# OSL · 天穹爭霸聯賽

四位參賽者，各在自己的Drive資料夾保留**一個SB3最強模型ZIP**。替換可刪舊上新，或用Drive「管理版本」上傳新版本；不依檔名猜最新模型。不需要上傳訓練程式、帳密或整個訓練資料夾。

## 賽制

- 四位同學與老師Rusher／Sniper共六席十五個配對；每對50個公開固定、分散的physical seeds，各交換座位一次，合計100場、全輪1500場。老師對手直接呼叫官方規則程式，不是模仿老師的神經模型。
- 雙方相同原版game.py、raw84輸入、native policy.predict(deterministic=True)、CPU單執行緒、1500tick上限。兩百萬policy參數上限。沒有同學權重訓練、人工改動作或額外資訊。
- 排名使用 `(勝 + 0.5 × 和) / 已完成場數`；完全相同比率同名次。未完成全輪時顯示暫列，缺模型或載入失敗不直接判輸。
- 每對手、座位拆分、W/L/D、勝率、積分率、physical-seed成群bootstrap區間、10場match、局長、原始事件與模型SHA可查。固定公開測試集的成績不能保證未知對手。
- 命中計數只包含真的對玩家產生擊落/終結的武器命中；不把射擊請求當發射、不把撞殺算成槍法，也不把平均值當單局保證。

## 雲端架構

網站由GitHub Pages提供。GitHub標準hosted Linux runner每5分鐘讀取Drive公開修訂資訊；沒有變更就不下載ZIP、不重跑比賽、不重新錄影、不重新部署網站。新版本才下載計算SHA並重跑受影響配對，未變的對手只在需要新配對時取回。每天另做一次內容SHA複核；修訂格式辨識失敗時退回內容雜湊，避免漏掉換版。**完全不使用self-hosted runner，不把比賽或訓練移到訪客瀏覽器。**瀏覽器只顯示已錄製狀態或播放MP4，正常網頁/影片解碼仍需基本裝置資源。

刷新網頁不是雲端執行觸發器。通常下一輪5分鐘檢查及比賽完成後可看到新版；GitHub排程可能延遲。需要立即排入可在「雲端賽程」的GitHub頁面按Run workflow；token不會放在公開網站。

官方檔案以Fernet加密fixture存放；解密金鑰只在GitHub Actions secret。公開repository不散布明文官方作業源碼或同學模型。執行模型的容器無網路、無token、非root、read-only根目錄、CPU/記憶體/執行時間限制。這保護雲端憑證，不把它宣稱為對惡意作弊模型的完整反作弊系統。

每場保存gzip視覺狀態與動作/觀測NPZ，所有對局均可播放、拖曳、換倍速；每配對另外輸出勝/敗/和/最長局最多四段官方renderer MP4，重播結果/步數核對。Canvas只畫錄製狀態，不含遊戲物理或模型。當模型改版，保留歷史成績與hash；首頁只保存目前版本的完整重播，避免無限堆積影片。歷史重播不是永久保存承諾。

目前標準public Actions compute免費，Pages免費；不使用付費大型runner或付費雲端服務。新版發布成功後刪除舊Pages artifacts，只留目前發布副本；驗證截圖保留一天、單份current release、無Actions cache。仍受GitHub/Drive政策、儲存與流量限制。

首次真實100場實測：整份當前資料（全部狀態重播、動作觀測與3段MP4）6,772,783 bytes；對戰＋錄影＋結果整理約63秒，另有建置／發布成本。600場的容量依局長而變，不能把此單次比例當固定承諾。

## 開發檢查

`python -m unittest discover -s tests` 只驗賽程/統計/格式，不在本機載入模型或跑對戰。正式遊戲、載入與影片檢查在雲端執行。

數據中心提供逐局、排名、兩兩勝率、座位、Match、戰鬥統計、模型版本七種UTF-8 BOM CSV。比例保留0–1原始數值。網站每分鐘讀取已發布資料；雲端檢查狀態每5分鐘讀一次GitHub公開狀態API，因此沒有換版也能看到最近檢查與倒數，不必重新發布整個網站。狀態API無法讀取時以最後成功資料時間標示等待，不捏造即時狀態。

歷史走勢以每次有效戰績變更為一個快照，可切換排名、每場積分率、總積分，點選選手可隱藏曲線。首筆結果只畫單點；未參賽者留空、不補0分。快照記錄時間、模型SHA、對手配對、場數與暫列/完整範圍，嵌入輕量manifest並提供ranking_history.json與UTF-8 BOM ranking_history.csv。無換版、僅刷新時間不增加快照；舊重播刪除不影響快照。不同對手版本/參賽人數的曲線不能直接解讀為單一模型變強。

## 五分鐘雲端檢查與失效提示

2026-10-20實測：GitHub `schedule` 雖為active，22:03後超過一小時沒有建立定時run，手動/push仍可正常執行；不是比賽或錄影一直重測。權限/預設main分支/公開非fork/未封存均核對正常；不能把具體根因未證明的排程停發硬說成單一高負載原因。

正常檢查改由 `poll-clock.yml` 的GitHub environment五分鐘server-side wait timer接續觸發 `league.yml`，同時安排下一個clock。等待期間不分配runner、不在電腦或VM內sleep；公開repository免費wait timer，使用本次job的短效GITHUB_TOKEN，不新增私人PAT。單一clock concurrency避免多條輪詢鏈；league單一concurrency避免重疊比賽。clock在17/47分有cron後備重啟、league每小時02分有獨立後備檢查。GitHub若整體API/runner/環境計時服務停擺仍可能延遲，不能保證外部平台永不故障。

網站每分鐘重讀已發布結果；五分鐘讀一次公開run狀態（手動刷新立即重讀）。顯示最近成功檢查、當前執行、下次clock預期時間、超時/失敗/API不可確認；不把過時成績叫做「已檢查但沒變更」。若要停止自動化，在Actions停用「五分鐘雲端時鐘」及「雲端賽事中心」兩workflow。沒有模型變更時維持manifest metadata-only快速檢查，無ZIP下載/遊戲/錄影/重新發布。


## 老師對手與20場觀看導覽

Rusher、Sniper列入同一排行榜，採老師原版raw84規則程式。官方source SHA與介面adapter SHA組成版本身分；無ZIP下載、無訓練或新增特權資訊。公開頁面只公開source雜湊與統計，不散布官方原始碼。兩兩比100場/50seed雙座位，包含Rusher對Sniper；第四位同學未上傳時明標暫列，不假造1500場。模型版本CSV另註明official_rulebot，非神經參數。

每配對仍保留100場完整狀態重播/動作觀測/數據，只轉最多4段MP4。預設20場觀看導覽：12個不看勝敗的固定seed（雙座位各6）＋最多8個勝敗/和局/逆轉/復活/雷射/長短局案例，整份清單雙座位各10；不足類別以接近中位局長補齊。導覽是行為觀察入口，不是勝率估計樣本；排名/信賴區間/CSV一律使用100場。可切回全部100場查任意seed。最多15×4=60段MP4，不把1500場逐一轉成MP4；狀態重播更省空間，實際容量與耗時仍以雲端紀錄為準。

舊同學配對沿用的前提：worker中原ZIP-vs-ZIP的load/play/audit/visual/render核心AST雜湊完全符合已保存相容錨點，使用原engine revision；任何核心改變就自動失效重測。新增官方controller的實作/原文身分另進bot版本雜湊。worker完整source SHA另記manifest，並非隱瞞程式改版或讓不相容結果混入。新的導覽由既有100份事件表產生，不重新玩遊戲。

### 歷史走勢的換版歸因

每個節點比對前後 SHA，列出同批所有換版者與完整前後版本。首次建榜、新增／移出對手、賽制變更及戰績補齊分別標示，不把所有新節點都當成換模型。舊歷史可補標，保留原節點與成績；歷史 CSV 同時匯出換版者及 SHA。這是已完成戰績的發布時間，不是 Drive 上傳時間，也不宣稱誰的更版造成勝率變化。
